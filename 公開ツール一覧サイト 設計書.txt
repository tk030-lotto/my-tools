# 公開ツール一覧サイト 設計書

## 1. 目的

GitHub Pagesを利用して、現在公開しているツールを一覧できるシンプルな紹介サイトを構築する。

このサイト自体を新しいサービスとして作り込むのではなく、

* 公開ツールの一覧
* 各ツールの簡単な説明
* GitHubリポジトリへのリンク
* note記事へのリンク

をまとめた「公開ツールのカタログ」として運用する。

## 2. 基本方針

サイトの役割を明確に分離する。

| 場所           | 役割              |
| ------------ | --------------- |
| GitHub Pages | 公開ツールの一覧・入口     |
| GitHub       | ソースコード・リポジトリ    |
| note         | ツールの紹介・開発経緯・使い方 |

GitHub Pagesにはnote記事の全文を転載せず、内容を短く要約して掲載する。

## 3. 掲載対象

原則として、現在公開しているツールのみを掲載する。

### 掲載するもの

* GitHubで公開されているツール
* noteで紹介記事が公開されているツール
* 現在も利用・閲覧可能なツール

### 掲載しないもの

* 開発中で未公開のもの
* 非公開リポジトリ
* 凍結・終了したプロジェクト
* ロト関連など、今回の一覧対象から除外するもの

## 4. サイト構成

初期バージョンでは1ページ構成とする。

```text
GitHub Pages
│
└── index.html
    │
    ├── サイト概要
    ├── 公開ツール一覧
    │   ├── AI開発
    │   ├── 開発支援
    │   ├── ファイル・PC
    │   └── その他
    │
    └── About / GitHub / note
```

個別ツールページは初期段階では作成しない。

ツール一覧から直接、

* GitHub
* note

へアクセスできるようにする。

## 5. トップページ

### ヘッダー

サイトタイトル：

**My Tools**

サブタイトル例：

> AIと一緒に作った公開ツールをまとめています。

説明文：

> 小さな面倒を減らすために作ったツールや、AI開発を支援するツールを公開しています。
> 詳しい内容はnote、ソースコードはGitHubをご覧ください。

## 6. ツール一覧

各ツールについて、以下の情報を表示する。

* ツール名
* カテゴリ
* 短い概要
* GitHubリンク
* noteリンク

表示例：

```text
PromptDiff

AI開発
プロンプトの変更点を比較するシンプルなツール。

[GitHub] [note]
```

## 7. note記事の要約

note記事の内容をサイト上で長く紹介する必要はない。

1ツールにつき、以下の3点を短くまとめる。

### ① 何のツールか

ツールの目的を1文で説明する。

### ② なぜ作ったか

どんな面倒・問題を解決するために作ったのかを1～2文で説明する。

### ③ 何ができるか

主な機能を簡潔に説明する。

全体として2～5行程度に収める。

詳細はnote記事へ誘導する。

## 8. ツール情報

ツールごとに管理する情報は以下とする。

```text
name
description
category
github_url
repository_name
note_url
status
```

必要に応じて以下を追加する。

```text
release_date
license
```

## 9. データ管理

初期バージョンではデータベースを使用しない。

ツール情報をJSONなどの静的データとして管理する。

例：

```json
{
  "name": "PromptDiff",
  "description": "プロンプトの差分を比較するツール",
  "category": "AI開発",
  "github_url": "GitHubのURL",
  "repository_name": "PromptDiff",
  "note_url": "note記事のURL",
  "status": "公開"
}
```

新しいツールを公開した場合は、データを1件追加するだけで一覧に反映できる構成を目指す。

## 10. ディレクトリ構成

初期構成は以下を想定する。

```text
my-tools/
│
├── index.html
├── css/
│   └── style.css
├── js/
│   └── app.js
└── data/
    └── tools.json
```

ツール数が少ない間は、さらに簡略化してもよい。

## 11. カテゴリ

初期カテゴリは以下を基本とする。

### AI開発

AI開発、AIコンテキスト管理、プロンプト関連など。

### 開発支援

JSON比較、ディレクトリ比較、Markdown関連など。

### ファイル・PC

ファイル名変更、デスクトップ整理、ディレクトリ可視化など。

### その他

上記に分類しにくい単機能ツール。

カテゴリはツール数の増加に合わせて見直す。

## 12. デザイン方針

デザインはシンプルにする。

重視するのは、

* ツールを探しやすい
* GitHubとnoteへすぐ移動できる
* スマートフォンでも見やすい
* ツール追加が簡単
* 保守が面倒にならない

ことである。

過度なアニメーションや複雑なUIは使用しない。

## 13. サイトの役割

このサイトは、noteやGitHubの代替ではない。

```text
                 ┌─────────────┐
                 │ GitHub Pages│
                 │   ツール一覧  │
                 └──────┬──────┘
                        │
             ┌──────────┴──────────┐
             ↓                     ↓
       ┌──────────┐          ┌──────────┐
       │  GitHub  │          │   note   │
       │ ソースコード│          │ 詳細記事   │
       └──────────┘          └──────────┘
```

GitHub Pagesは「入口」と「目録」に徹する。

## 14. 初期掲載作業

最初に、現在noteで公開しているツール記事を確認し、各記事から以下を収集する。

* ツール名
* note記事URL
* GitHubページURL
* GitHubリポジトリ名
* ツール概要
* カテゴリ

これを一覧化してから、GitHub Pagesへ登録する。

特にURLは手入力で推測せず、**実際のnote記事に記載されているURLをそのまま使用する。**

## 15. 今後の運用

新しいツールを公開した場合は、

1. GitHubリポジトリを公開
2. noteで紹介記事を公開
3. GitHub Pagesのツール一覧に追加
4. 概要を2～5行程度で記載
5. GitHubとnoteのリンクを登録

という流れにする。

これにより、ツールが増えてもサイト更新の負担を最小限にする。

## 16. 将来的な拡張

初期バージョンでは実装しないが、必要になった場合は以下を追加できる。

* キーワード検索
* カテゴリフィルター
* 公開日順表示
* GitHub Star数の表示
* 更新状況の表示
* ツールのスクリーンショット
* 個別ツールページ
* GitHub APIによる情報取得

ただし、ツール数が増えて実際に必要になるまでは実装しない。

## 17. 最終コンセプト

このサイトは「立派なポートフォリオサイト」を目指さない。

**「現在公開しているツールが、ここを見れば全部わかる」**

ことを最優先とする。

GitHubは実物、noteは物語、GitHub Pagesは目録。

この3つをつなぐことで、既存の活動を活かしながら、公開ツールを探しやすくする。
